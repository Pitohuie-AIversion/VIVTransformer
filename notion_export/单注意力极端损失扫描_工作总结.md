# 单注意力极端损失扫描 工作总结

> 项目根目录：`X:\2025\Graduation_project\Pdebench_input_Transformer\VIVTransformer-1`

## 1. 目标与范围
- 针对单一注意力机制（如 s2、eca、bam 等），批量扫描一组“极端”损失权重组合（base 和 SVD 模态权重）对验证损失的影响。
- 通过统一的动态分辨率训练器进行训练，记录曲线并自动生成对比图，便于挑选更优的损失配置。

## 2. 环境与硬件
- OS：Windows 11
- Python：3.12.7
- PyTorch：2.6.0 + cu126
- CUDA：12.6
- GPU：NVIDIA GeForce RTX 4090（22.5 GB，单卡，ID 0）
- CPU：32 核

## 3. 关键脚本与配置
- 训练编排脚本：`utils_server/single_attention_loss_scan.py`
  - 作用：按给定注意力类型与极端损失组合批量启动训练；优先读取 server 专用基底配置，动态生成临时配置文件，并在结束后自动绘图。
- 基底配置（单注意力极端损失扫描专用）：`generate_data/dynamic_config_server_single_attention_loss_scan.yaml`
  - 作用：提供数据、DataLoader、训练、损失等默认配置。脚本会在其基础上注入 `loss_configs` 和 CLI 覆盖项。
- 动态分辨率训练器：`generate_data/dynamic_resolution_trainer.py`
  - 作用：实际执行训练；接收 `--config`、`--attention-type`、`--loss_idx`、`--epochs`、`--num-samples` 等参数。

## 4. 已完成的调整与约定
- `single_attention_loss_scan.py` 默认适配单卡 Windows：
  - `--gpus` 默认值：`"0"`
  - `--max-per-gpu` 默认值：`1`
  - 生成临时配置时优先使用 `generate_data/dynamic_config_server_single_attention_loss_scan.yaml`，若不存在回退 `generate_data/dynamic_config.yaml`。
- 数据路径通过 CLI 指定：`--data-path "F:\\Zhaoyang\\VIVTransformer_pdebench\\2D_DarcyFlow_beta0.1_Train.hdf5"`
- CLI `--max-samples` 会映射为训练器的 `--num-samples` 并覆盖 YAML 中的 `data.num_samples`。

## 5. 推荐运行方案（PowerShell 下直接运行）

### 方案 A：快速验证（50 epoch，200 样本）
```powershell
python utils_server/single_attention_loss_scan.py \
  -A s2 -N 10 -E 50 -G 0 -M 1 \
  --batch-size 80 --max-samples 200 \
  --data-path "F:\Zhaoyang\VIVTransformer_pdebench\2D_DarcyFlow_beta0.1_Train.hdf5" \
  --run-id s2_e50_b80_m200_darcy
```

### 方案 B：稍激进/长跑（1000 epoch，尽量用满数据）
```powershell
python utils_server/single_attention_loss_scan.py \
  -A s2 -N 10 -E 1000 -G 0 -M 1 \
  --batch-size 80 --max-samples 10000 \
  --data-path "F:\Zhaoyang\VIVTransformer_pdebench\2D_DarcyFlow_beta0.1_Train.hdf5" \
  --run-id s2_e1000_b80_m10000_darcy \
  --timeout-seconds 0
```

可选开关：
- 仅基于已有结果重绘曲线（不训练）：`--replot-only --run-id <你的run_id>`
- 跳过已存在的配置日志（便于续跑）：`--skip-existing`

## 6. 产出与目录结构
- 训练与日志：`attention_results/loss_config_<i>/<attention>/run_<run_id>/`
  - 日志：`loss_logs/loss_log.txt`
  - 其他：训练过程中保存的中间结果、可视化、（若开启 checkpoint）模型权重等
- 对比图（根目录下）：`<attention>_extreme_loss_comparison_<run_id>.png`
- 临时配置（运行时生成并自动清理）：`temp_extreme_loss_config.yaml`

## 7. 参数建议（基于当前硬件）
- Batch：`80`（显存 22.5GB，s2 模块一般可承载。若 OOM，降到 64 或 48）
- DataLoader：
  - YAML 默认：`num_workers: 8, pin_memory: true, persistent_workers: true, prefetch_factor: 4`
  - 可按 CPU 32 核适度上调到 `num_workers: 12`，如遇到卡顿或频繁重启 worker，回退到 `8` 并考虑将 `persistent_workers: false`
- 混合精度：开启（YAML 已启用），可配合 `max_memory_fraction: 0.9`
- 早停：默认启用；如需严格跑满 `1000` epoch，建议临时关闭或提高 `patience`（例如 100）

## 8. 常见问题与排查
- DataLoader 卡住/变慢：降低 `num_workers` 或将 `persistent_workers` 设为 `false`；检查数据盘读写负载（当前数据在 `F:` 盘）
- 显存不足（OOM）：降低 `--batch-size`；确保混合精度开启；必要时降低 `input/output_resolution` 或 `svd_projection.n_modes`
- 结果被覆盖：务必使用独立的 `--run-id`（包含关键信息，如 `s2_e1000_b80_m10000_darcy`）
- 进程超时：长跑场景使用 `--timeout-seconds 0`（不设超时），或根据经验设置一个较大的秒数
